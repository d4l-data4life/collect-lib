# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

### Changed

### Deprecated

### Removed

### Fixed

### Security

## [v1.59.2] - 2026-11-09

### Changed

- Add `google-health`, `garmin` and `oura` to HealthConnectDataSource

## [v1.59.1] - 2026-11-04

### Changed

- Replace `skinTemperature` by `skinTemperatureDeviation` for Google Health

## [v1.59.0] - 2026-11-03

### Added

- shared annotation items `DEVICE_ANNOTATION_ITEM_ACTIVE_CALORIES`, `DEVICE_ANNOTATION_ITEM_DAILY_CALORIES_TOTAL` and `DEVICE_ANNOTATION_ITEM_DAILY_STEPS_TOTAL`

### Changed

- **Breaking:** data types renamed, per device:
- naming scheme: `steps` counts one interval, `dailySteps` is a running total since local midnight, `dailyStepsTotal` is one value per completed day (same for `calories` / `dailyCalories` / `dailyCaloriesTotal`; calories are the total burn, `activeCalories` the activity burn only)
- **Breaking:** the RMSSD annotation item type is `hrvRmssd` instead of `hrv`

## [v1.58.1] - 2026-10-29

### Fixed

- `BleDeviceMetaLabel` accepts labels in every program language
- `toDeviceConfig` keeps device label translations for all program languages

## [v1.58.0] - 2026-10-20

### Added

- config and constants for the generated byod device-selection questionnaire

## [v1.57.1] - 2026-10-19

### Removed

- Health Connect data points calories, distance and heart rate, and the grouping of exercise data points under `exercise`: exercise session, power, speed and VO2 max are now separate data points

## [v1.57.0] - 2026-10-13

### Added

- Health Connect `exercise` data type, expanded by `toDeviceConfig` / `toHealthConnectSignalTypes` into the signal types `exerciseSession`, `exerciseCalories`, `exerciseDistance`, `exerciseHeartRate`, `exercisePower`, `exerciseSpeed` and `exerciseVo2max` (new annotations, annotation item types `exerciseType`, `power` and `vo2maxMeasurementMethod`)

### Changed

- Google Health HRV annotation is RMSSD-only (`DEVICE_ANNOTATION_ITEM_HRV_RMSSD` + data source) instead of the 4-channel Fitbit item, dropping the always-empty coverage/hf/lf columns

## [v1.56.0] - 2026-10-12

### Added

- code → label tables for `sleepLevel`, `sleepState`, `sleepStage` and `activityDetection`, so `phoenix` can import instead of maintaining its own copy

## [v1.55.0] - 2026-10-08

### Added

- Google Health annotations for `restingHeartRate`, `distance`, `floors`, `elevationGain`, `activeZoneMinutes`, `activity` and `vo2max`; new data types `distance`, `floors`, `elevationGain` and `activeZoneMinutes` (annotation item types `floors`, `elevationGain`, `heartRateZone`, `activeZoneMinutes`)
- `GoogleHealthDataSource` / `GOOGLE_HEALTH_DATA_SOURCES` (`phone`, `reconciled`, `unknown` or the source device's slug), accepted by `encodeDataSource`

### Changed

- Every Google Health annotation now ends with the 16-byte `dataSource` item, and the interval signals (`steps`, `calories`, `distance`, `floors`, `elevationGain`, `activeZoneMinutes`, `activity`) carry the interval length as `duration`; the eight original signals are therefore no longer byte-identical to their Fitbit annotations (`GOOGLE_HEALTH_*_ANNOTATION`)

### Fixed

- `Requester` now throws `RequesterError`, carrying the response `status`, so callers can branch on the HTTP status instead of only the body text (`registerDonor`'s 409/500 cases were unreachable)

## [v1.54.0] - 2026-09-25

### Changed

- Renamed device key `PixelWatch1` to `PixelWatch` (`DEVICE_KEY_BLE`, `ProgramDeviceType`, `DEVICE_KEY_TO_NAME`) to cover all Pixel Watch generations
- Bump actions for Node 24 runner compatibility

## [v1.53.0] - 2026-09-10

### Added

- Line Systems (Line Portal) device type `LINE_SYSTEMS` with the data types `cgm`, `bolus`, `basal`, `bgm` and `deviceEvents` and their binary annotations
- Donor access tokens from the data-dispatcher: `DonationSDK.requestAccessToken` (`POST /access-token`, self-signed donor auth) and the caching `DonationSDK.getAccessToken` (reused until 30 s before expiry, single-flight per donor); `AccessTokenProvider` type

### Changed

- **Breaking:** `CollectorClient` authenticates with a dispatcher-issued donor access token (`Authorization: Bearer <accessToken>`) instead of the self-signed scheme; its constructor is now `(accessToken: AccessTokenProvider, collectorURL)` and no longer takes the self-sign secret, converter or crypto module. The collector's `GET /token` is no longer called and `buildSelfSignedAuthToken` was removed

## [v1.44.0] - 2026-07-31

### Added

- Garmin support: `GARMIN` API target, device config, annotations and routine type.
- `CollectorClient` for the data-collector (study-scoped `connect`/`sync`/`ack`/`disconnect`);
- v4 hybrid encryption (slot-based, shared with go-crypto): `HybridEncrypter.encryptV4` with
  v3 fallback). `decryptV4WithKeys` takes an explicit keychain (`v4AesKey` / `v4RsaKey` /
- `KeyHandler.deriveEncryptionKeypair`: the phone's secp256k1 encryption keypair, derived
  deterministically from the donor identity.
- Export `HybridEncrypter` and the collector SDK.

### Changed

- `@noble/curves` now requires `^1.9.3` (was `^1.8.2`) for `secp256k1.utils.isValidSecretKey`.

### Fixed

- `uint8ArrayToBinaryString` threw `RangeError: Maximum call stack size exceeded` beyond
- `KeyHandler.verify` could not verify `KeyHandler.sign`'s own signatures (hex digest and
  SPKI public key were passed in the wrong encodings).
- `encryptDonation` propagates errors instead of returning an empty object, which produced
  malformed donations.
